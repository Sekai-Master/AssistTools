# 「スコア0イベ乙」— 最後の1本を叩かずに締めるオプション

2026-07-23 提案。3周目で実装予定。ブリーフ本体は `point-adjust-step2-ux-brief.md`。

## 何をするか

調整の**最後の1本をスコア0（叩かない＝放置）で実行**し、その最低獲得Ptで目標に着地させる。
コミュニティで「スコア0イベ乙」と呼ばれている締め方。

## なぜ価値があるか

通常プランの各ユニットはスコア帯（2万点幅）に着地させる必要がある。
総合力が高いほど「低い帯にわざと落とす」のは難しく、実行時の分散が残る。
スコア0は**叩かなければ確定**するので分散がゼロになる。

決定的なのは、**ミスの回復可能性が途中と最後で違う**こと:

- 途中のライブで外した → 残額を測り直して残りを再計算すれば吸収できる
- **最後の1本で外した → 超過なら取り返しがつかない**（ポイントは減らせない）

したがってリスクを潰す費用対効果は最後の1本が最大。全部を決定論にする必要はない。

## 全ライブをスコア0にするのは破綻する（実測）

ボーナス990%・基礎点28種・LB0〜10で到達値を全数列挙した結果:

| 方式 | 1本の到達値 | 2本以内 | 3本以内 | 4本以内 |
|---|---|---|---|---|
| 全ライブ スコア0 | **308通り** | 14.6% | 58.7% | 86.6% |
| 通常（スコア上限110万） | 7,386通り | 69.5% | **99.2%** | 99.2% |

被覆率は残額 1〜200,000 の整数に対する到達率。
**全ライブをスコア0に縛ると4本使っても13%が着地不能**。到達値が308通りしかないため。

## 最後の1本だけスコア0なら被覆100%（実測）

「通常3本以内 + スコア0の締め1本」で、**残額 7,000〜100,000 の全整数（93,001通り）が到達可能**。
漏れなし。実用上これで十分。

## 実装方針

オプション「**最後はスコア0で締める**」（既定OFF。+1本ぶんの時間コストがあるため）

1. 締めの値を先に予約する。`calcLivePt(基礎点, bonus, 0, LB)` の値から選ぶ
   - 最短は独りんぼエンヴィー（74.8秒）。LB0 なら 1,090（ボーナス990%時）
   - LBを上げれば 5,450 / 10,900 / 16,350 … と選択肢が増え、残額の調整幅が広がる
2. `目標 − 締めの値` を通常の探索で解く
3. 最後に「叩かない1本」をプランの末尾に提示する

時間コストはエビ使用で 74.8 + 47 = 約2分。**実行の確実性を約2分で買う**取引になる。

## UI

- 用語「スコア0イベ乙」をそのまま出す（知っている人には一発で伝わる）
- 知らない人向けに「最後の1本は叩かずに終えます。ミスによるズレが起きません」を添える
- 締めの1本は他のユニットと視覚的に区別する（スコア帯の表示が不要なため）

## 注意

- 締めの値はボーナス依存。ハードコードせず `calcLivePt` から導出すること
- 締めに使える最小値 = 最小基礎点 × LB0 × スコア0。これは `MultiLiveAdjustResult.minPtPerLive` と同一
  （旧 `landability.ts` モジュールは配線先が無く削除済み。判定は `landability` フィールドが担う）
- 残額が締めの値そのものと一致する場合、調整ライブ0本＋締め1本で完了する
