# アクセス解析を手元から読む

Cloudflare Web Analytics の数字を、ダッシュボードを開かずに読むための手順。

**ダッシュボードで1回見るだけなら、これは要らない。** 用意する価値があるのは「告知の効果を毎回測る」「月次で定点観測する」のように**繰り返す**とき。

## なぜトークンが要るか

サイトの HTML に載っているビーコンのトークン（`data-cf-beacon` の値）は**送信専用**で、読み出しには使えない。`wrangler` のログインで得られる OAuth トークンにも解析の読み取り権限は含まれていない（実際に 401 になる）。読むには**解析の読み取り権限を持つ API トークン**を別に作る必要がある。

## 1. トークンを作る（Cloudflare）

1. <https://dash.cloudflare.com> にログイン（**Pages と同じアカウント**。複数ある場合は取り違えに注意）
2. 右上のアイコン → **マイ プロフィール** → **API トークン** → **トークンを作成する**
3. 一番下の **カスタム トークンを作成する** → 「開始する」
4. 名前: `sekaimaster-analytics-read` など
5. **アクセス許可**（これだけ。他は足さない）

   | 種別 | 項目 | 権限 |
   |---|---|---|
   | アカウント | **Account Analytics** | **読み取り** |

6. **アカウント リソース**: 「含める」→ 自分のアカウントを選ぶ
7. TTL は任意。期限を切っておくと安全（切れたら作り直す）
8. 「概要に進む」→「トークンを作成する」→ **表示された値をコピー**（この画面を閉じると二度と見られない）

**書き込み権限は付けない。** 読むだけの用途なので、漏れたときの被害を最小にする。

## 2. 手元に置く

```bash
cd C:\Users\masan\Documents\GitHub\AssistTools
copy .env.example .env
# .env を開いて CF_ANALYTICS_TOKEN= の右に貼る
```

- **`.env` は gitignore 済み**。コミットされない
- **チャットに貼らない。** ファイルに直接書く
- 値を変えたい／漏れたと思ったら、Cloudflare の API トークン画面から**ロール（再生成）または削除**する

## 3. 読む

```bash
npm run analytics          # 直近7日
npm run analytics -- 30    # 直近30日
```

出るもの: ページビューと訪問数、日別、**時間帯（JST）**、ページ別、リファラー、端末、国。

見どころは3つ。

- **ページ別** — どのツールが実際に使われているか。次にどこへ手を入れるかの根拠
- **時間帯** — 告知を何時に出すかを実測で決める材料。「21時が定石」は業界の一般論であって、このサイトの実測ではない
- **リファラー** — `t.co` が立っていれば X の告知が効いている。`(直接)` ばかりならブックマーク経由

## 困ったとき

| 症状 | 原因 |
|---|---|
| `401` / `403` | トークンの権限不足。**Account Analytics: 読み取り**が付いているか確認 |
| 数字が全部 0 | 期間の指定か、ビーコンが入っていない。`curl -s "https://sekaimaster.pages.dev/?v=1" \| grep -c cloudflareinsights` が 1 なら入っている |
| 自分の確認分が混ざる | ヘッドレスブラウザで本番を開くとビーコンが飛ぶ。計測用に本番を叩いたらその旨を控えておく |
