# 効率曲ランキング 実機測定プラン（2026-07-30）

効率曲ランキングの計算モデルを、指定した編成で実際にプレイして検証するための手順書。
「調べたら分かる」の限界に来たので、ここから先は実測で決める。

参照実装は [xfl03/sekai-calculator](https://github.com/xfl03/sekai-calculator) の
`src/live-score/live-calculator.ts` と `src/event-point/event-calculator.ts`。
データは sekai.best の `music_metas.json`。実装側は `src/pages/ranking/lib/efficiency.ts`。

---

## 0. なぜ実測が必要になったか

ぐみみさん（[@gmm_prsk](https://x.com/gmm_prsk)）が公開している難易度別スコアランキングと、
こちらの計算で順位が食い違う。原因を机上で詰めようとして、次のところまでは分かった。

- あの表の APPEND 順（群青讃歌 > ビバハピ > ヒバナ -Reloaded-）は、
  **全枠に同じスコアアップ%を置くモデルではどんな値でも再現できない**。
  群青 > ビバハピ は「一律スキル < 79.6%」を、群青 > ヒバナ は「> 98.4%」を要求して矛盾する。
- 発動順を最良に固定した「上振れ」モデル、5枚の値をばらした編成、協力/オートの重み、
  スキル無し（base のみ）まで当てて最小二乗で合わせたが、RMSE は 11,000〜18,000 で下がらない。
  特に **怪獣になりたい APPEND の位置が系統的にズレる**（あちらは4位、こちらの全モデルで最下位）。
- つまり、あの表は現在の `music_metas.json` から導ける値ではない。
  別データか、譜面を自前で採譜したノート単位シミュレータの出力と考えるのが自然
  （[そういう自作シミュレータの例](https://nanaev.hatenablog.jp/entry/2022/02/20/185225)がある）。

二次情報どうしを突き合わせても、どちらが正しいかは決まらない。**自分で測る。**

## 1. 確かめたいこと

| # | 未確定 | 現在の実装の前提 |
|---|---|---|

## 2. 測定設計の原則

確度は「何回やるか」より「交絡をどう潰すか」で決まる。以下は全実験の共通ルール。

1. **AP（全ノーツPERFECT）必須。** 判定係数を1に固定するため。
   1ノーツでも落ちたデータは原則破棄する（E4・E6 は例外で、意図的に落とす）。
2. **同じ5枚のまま、リーダー（一番左）だけ入れ替える。**
   総合力も内部値も変わらないので、差の原因がリーダー枠の効果だけに絞られる。
   カードを差し替えると総合力が動いて何を測ったか分からなくなる。
3. **サブ4枚のスコアアップ%を揃える。**
   揃っていないとサブ同士の並び替えでもスコアが動いて、リーダーの枠が読めなくなる。
   スキルの種類（判定強化・ライフ回復）は違ってもよい。APならスコアに効くのはスコアアップ%だけ。
4. **リーダーとサブの差を大きく取る。** 40%以上あると枠がはっきり読める。
5. **ひとりでライブは0焚きで何度でも回せる。** 反復コストは時間だけ。ここを主戦場にする。
6. **協力ライブは1人部屋でやる。** 他人のスコアが0になり、Pt式の他人項が消えて切り分けやすい。
7. **総合力は毎回ゲーム内の表示を記録する。** エリアアイテムやキャラランクで変わる。
8. **予測を先に出す。** 叩いてから式をいじると、必ず後付けの説明ができてしまう。
   `node scripts/predict-score.mjs` で期待値を出し、この文書に貼ってからプレイする。

## 3. 使う譜面

### メイン: イレヴンス HARD

| 項目 | 値 |
|---|---|
| Lv | 16 |
| ノーツ | 419 |
| 曲長 | 98.1秒 |
| 基礎点 | 107 |
| base_score | 1.075329 |
| 枠1〜5の重み | 0.025223 / 0.049270 / 0.067935 / 0.083523 / 0.102159 |
| 6枠目（アンコール）の重み | 0.067398 |
| 協力の重み | 枠4だけ 0.083523 → 0.125284（×1.5）。**枠4がフィーバー区間に重なっている** |
| fever_score | 0.148402 |

**この譜面を選んだ理由:**

- 5枠の重みが**単調増加**で、**隣り合う枠でも十分に離れている**（最小差 0.0156）。
  総合力30万・リーダーとサブの差90%なら、枠が1つ違うだけでスコアが**約1万点**変わる。
  スコアを見ればリーダーが何枠目に入ったかが一意に決まる。全曲を走査して最良だった。
- Lv16 なので AP しやすい。419ノーツ・98秒で1周が速く、反復に向く。
- **基礎点が107**（100でない）ので、イベントPtの丸め検証（E5）も同じ譜面でできる。
  基礎点100だと丸め方式の違いが数学的に消えてしまい判別できない。

### 予備: ドリーマーズビート EASY（Lv6 / 203notes / 102.4秒 / 基礎点107）

APが不安なとき、あるいは操作に慣らすとき用。枠の重みは
0.026471 / 0.038824 / 0.080294 / 0.065056 / 0.055253、6枠目 0.086444。
単調でないので枠の読み取りはイレヴンスより弱いが、最小差 0.0098 で約1万点差はつく。

## 4. 実験

### E1 ソロの枠重みと発動順のランダム性【最優先】

**これ単独で U1・U2・U3・U7 に同時に答えが出る。他の実験の土台。**

- **譜面**: イレヴンス HARD
- **編成**: リーダー1枚（高スコアアップ）＋サブ4枚（同じスコアアップ%、リーダーと40%以上差）
- **設定**: ひとりでライブ / 0焚き
- **回数**: 10〜15回（AP成功ぶんだけ）
- **記録**: 毎回のスコア（1点まで）。総合力・各カードのスコアアップ%も1回だけ記録

**判定基準:**

| 観測 | 結論 |
|---|---|
| スコアが予測5値に散る | モデル通り。ランダム＋6枠目はリーダー固定。出現回数から分布も取れる（一様なら各20%） |
| 常に同じ値 | 発動順は固定。どの予測値と一致したかで並び順が確定する |
| 予測5値のどれとも合わない（全体が一定量ずれる） | base か総合力の使い方（U7）が違う。ズレは全予測に同じ量で乗るので見分けられる |
| 散るが予測値と一致しない | 枠重み（U3）が違う。観測値から重みを逆算できる |

**注意**: サブ4枚が揃っていないと予測が5通りでは済まなくなる。揃えられないなら、
`predict-score.mjs` が警告を出すので、その場合は E1 を諦めて E2 の差分測定に寄せる。

### E2 6枠目がリーダーかの裏取り

- E1 と**同じ5枚**のまま、リーダーをサブの1枚と入れ替える（一番左を差し替え）
- 同じ手順で10回
- **予測**: 予測5値の全体が `(新リーダー − 旧リーダー) × 0.067398 / 100 × 総合力 × 4` だけシフトする
- シフトしなければ「6回目はリーダー」が誤り。シフト量が合わなければ6枠目の重みが違う

### E3 協力ライブの実効値【重要】

**ソロと協力で「同じ操作への反応の大きさが約7倍違う」ことを使う。**
リーダーを ΔL だけ変えたとき:

- ソロ … 6枠目の重みぶんだけ効く → `ΔL × 0.067398`
- 協力 … 実効値が `0.8 × ΔL` 動き、それが**全6枠の合計**に乗る → `0.8 × ΔL × 0.488` ≒ `ΔL × 0.390`

**比が 5.8倍。** どちらのモデルかを一発で切り分けられる。

- **設定**: 協力ライブ・**1人部屋**（自分だけで開始）/ 0焚き
- **手順**: E1 の編成で5回 → E2 の編成（リーダー入れ替え）で5回
- **要確認**: 1人で協力ライブが開始できるか。フィーバーが発生するか。
  できない場合は2人部屋にして、**相方のスコアも必ず記録**する

### E4 フィーバー加点

- **設定**: 協力ライブ・1人部屋 / 同じ譜面・同じ編成
- **(a)** AP・フィーバー成功
- **(b)** フィーバー区間で**1ノーツだけGOODにして**フィーバー不成立、残りはPERFECT
- **予測**: 差 = `fever_score × 0.5 × 総合力 × 4`（`predict-score.mjs --live multi` が出す）
- **注意**: (b) は外したノーツの判定係数ぶんも引かれる。落としたノーツの種類と数を必ず記録。
  イレヴンスは協力の重みが枠4だけ1.5倍なので、**フィーバー区間は枠4のあたり**にある

### E5 イベントPtの式と丸め

イベント期間中に行う（ひとりでライブでもイベントPtは入る）。
ボーナスは**0%**（イベント編成を組まない）にすると式が単純になって切り分けやすい。

1. ひとりでライブ・0焚き → スコアと獲得Ptを記録。ソロ式 `100 + floor(スコア/20000)` と丸めを検証
2. 協力1人部屋・0焚き → 係数が `110 + floor(自/17000)` になっているか（他人項が0のはず）
3. 2人部屋・0焚き → 相方のスコアも記録し、`min(13, floor(他/340000))` を検算
4. 焚き数を変えて倍率表（5焚き=25倍・7焚き=29倍）を確認。1回で足りる

基礎点107 の譜面なので、`floor(val2 × 10) / 10`（小数第1位保持）が
他の丸め方式と違う値になる。ここが本命の検証点。

### E6 GREAT の判定係数【低優先】

EASY 譜面でわざと数ノーツを GREAT にして、判定係数0.7を検証する。
ノーツごとの寄与が均等でないため誤差が大きく、確度は低い。E1〜E5 が片付いてから。

## 5. 記録フォーマット

そのままコピペして埋められる形。1プレイ1行。

```
| # | 日時 | 譜面 | 難易度 | 種別 | 総合力 | リーダー% | サブ% | 内部値 | 焚き | ボーナス% | 判定 | スコア | 獲得Pt | 備考 |
|---|------|------|--------|------|--------|-----------|-------|--------|------|-----------|------|--------|--------|------|
| 1 |      |イレヴンス| HARD | ソロ |        |           |       |        |  0   |           | AP   |        |        |      |
```

- **種別**: ソロ / 協力1人 / 協力2人 / オート / チャレライ
- **判定**: `AP` / `FC(GREAT3)` / `MISS1` のように書く。AP以外は E4・E6 でのみ使う
- **備考**: 部屋に他人がいたらその人のスコア、フィーバーの成否、落としたノーツの位置

## 7. 事前登録（プレイ前にやること）

1. 編成を組む（サブ4枚のスコアアップ%を揃える）
2. ゲーム内で**総合力**と**各カードのスコアアップ%**を確認して控える
3. 予測を出す:

```bash
node scripts/predict-score.mjs --song イレヴンス --diff hard \
  --power <総合力> --deck <リーダー>,<サブ>,<サブ>,<サブ>,<サブ> --bonus 0 --taki 0

# 協力ライブ側
node scripts/predict-score.mjs --song イレヴンス --diff hard \
  --power <総合力> --deck ... --live multi --bonus 0 --taki 0
```

4. 出力をこの文書の下に貼る
5. **それから**プレイする

出力例（総合力303,417 / 編成 150,110,110,110,110）:

```
リーダーの枠  枠の重み    予測スコア   予測イベントPt
      1      0.025223   1,878,073      1,032
      2      0.049270   1,889,747      1,037
      3      0.067935   1,898,809      1,037
      4      0.083523   1,906,376      1,043
      5      0.102159   1,915,423      1,043

下振れ 1,878,073 〜 上振れ 1,915,423（幅 37,350）／ 期待値 1,897,686
```

隣り合う枠で約1万点差。**スコアを見ればリーダーが何枠目に入ったか一意に決まる。**

## 8. 事前登録した予測（2026-07-30・第1回）

**プレイ前に固定した値。ここから下は書き換えない。**

- 編成: リーダー **140%** ／ サブ **80% × 4**（内部値 **460**、実効値 **204**）
- 総合力: **255,528**
- イベントボーナス: **170%**
- 譜面: イレヴンス HARD（Lv16 / 419notes / 98.1秒 / 基礎点107）

### E1: ひとりでライブ・0焚き・AP

| リーダーの枠 | 枠の重み | 予測スコア | 予測イベントPt |
|---|---|---|---|
| 1 | 0.025223 | **1,479,310** | 499 |
| 2 | 0.049270 | **1,494,058** | 502 |
| 3 | 0.067935 | **1,505,504** | 505 |
| 4 | 0.083523 | **1,515,064** | 505 |
| 5 | 0.102159 | **1,526,493** | 508 |

下振れ 1,479,310 〜 上振れ 1,526,493（幅 47,183）／ **期待値 1,504,086**

隣り合う枠の差は 9,560〜14,748 点。スコアからリーダーの枠が一意に決まる。
獲得Ptも同時に記録すれば E5 のステップ1（ソロ式と丸めの検証）を兼ねられる。

### E2: リーダーを80%のカードに入れ替え（同じ5枚のまま）

サブ側に140%が混ざるため個々の値は5通りでは済まないが、**平均は必ず下がる**。

- 予測: 期待値が **1,504,086 → 1,462,753**（**−41,333**）
- この差は `(140 − 80) × 0.067398 / 100 × 255,528 × 4` そのもの。
  ずれたら6枠目の重みか「6回目はリーダー」が誤り。

### E3・E4: 協力ライブ（1人部屋）・0焚き・AP

- 実効値 = 140 + (460 − 140) × 0.2 = **204.0**
- 予測スコア（フィーバー成功）: **2,086,701**
- 予測スコア（フィーバー不成立）: **2,010,859**
- 差 **75,842** が `fever_score × 0.5` ぶん（E4の検証点）
- 予測イベントPt（1人部屋・他人0）: **670**
- 予測イベントPt（同格5人）: **707**

**切り分けの要点**: リーダーを140→80に入れ替えたとき（同じ5枚のまま）のスコアの下がり方。

| モデル | 予測される下がり方 |
|---|---|
| 実効値モデル（実装の前提） | **−214,530**（実効値が 204 → 156 に動き、全6枠に乗る） |
| 協力もソロと同じ「6枠目だけリーダー」だった場合 | **−41,333** |

**5.19倍違う。** 1回叩けば決着する。しかも協力は編成が同じなら毎回同じスコアになるはず
（実効値は6枠すべてに同じ値が乗るので、発動順がランダムでも揺れない）。
**揺れたらその時点で実効値モデルが誤り**という副次的な判定もできる。

### E5補: チャレンジライブ

チャレライは1日1回なので測定には使わず、消化ついでに記録するだけでよい。
Pt式が `(100 + floor(スコア/20000)) × 120` で**ボーナス・基礎点・焚き数と無関係**という
特殊形なので、1プレイぶんのスコアと獲得Ptがあれば検証できる。
