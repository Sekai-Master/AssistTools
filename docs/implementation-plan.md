# 実装計画: ゲージのタイマー入力・マイセカイのPt・休憩中オート

対象: `/refresh`（リフレッシュゲージ計算機）と `/plan`（周回プラン）。
依頼は Nori（2026-08-27）。**イベントの途中からツールを開いても、いまの状態がそのまま入力できること**が主題。

## なぜ要るか

1. **途中参加でタイマーの位置が分からない。** いまのタイムラインは「たった今プレイを止めた」前提（減少タイマーの進捗0）で始まる。
   実際にはイベント中のどこかで開くので、**最大30分ぶん予定がずれる**。ゲーム内の「次の回復まで ○分」を入れれば一意に決まる。
2. **休憩がPtを産まないことになっている。** オート・チャレライは**ゲージが増えない**種別で、100%でもPtが入る（公式文言 / evenran spec §5-2）。
   つまり休憩は「Ptを稼ぎながら」実行できるのに、プランでは0点の空白として扱っている。
3. **マイセカイが0点。** 単価は総合力とボーナスから出せる（`calculateUnitBasePt`）のに、プランのマイセカイブロックはゲージしか動かさない。

## フェーズ

### Phase 1: ゲージの減少タイマーを入力できるようにする（/refresh・/plan 共通）

- `lib/gaugeModel.ts` に純関数を足す: 残り減少回数・現在ゲージからの全回復分・「次の回復まで」→タイマー進捗
- `lib/timeline.ts` の `simulateTimeline` に開始時のタイマー進捗（分）を渡せるようにする（既定0＝従来と同一）
- `useGaugeInputs` / `GaugeInputsPanel` に「次の回復まで ○分」を追加（空欄可。空なら従来どおり30分フル扱い）
- `/refresh` の「全回復まで6時間」を**いまのゲージからの全回復まで**に変える
- 保存プラン（`planStorage`）に持たせる。旧データは欠けていても壊れない

### Phase 2: マイセカイのPt概算（/plan）

- マイセカイブロックの入力を**メモリ数**にする（旧データのスタミナは 1メモリ=5スタミナ で読み替え）
- 「全回収」プリセット（既定 89.5 メモリ）
- 総合力・イベントボーナス・ワールドパスを `/plan` に持たせ、`calculateUnitBasePt` で単価を出す。編成プロフィールから流し込める
- Pt の計算は `lib/planPoints.ts` に切り出して単体テストする（いまは `PlanTimeline` の中に埋まっている）

### Phase 3: 休憩中のオート（/plan）

- 休憩ブロックに「オートを回す」を足す。**ゲージは増えない**ので減少はそのまま進む（＝休憩としての価値を失わない）
- 1回あたりPtは**曲＋難易度から自動計算**（`useRankingMusics(enabled)` で必要になったときだけ読む）。実測があれば上書き入力できる
- `lib/autoPlan.ts`（純関数・テスト付き）で弾く:
  - **回数上限**: パス種別（10/99）と「今日すでに回した回数」から、ゲーム日（4:00区切り）ごとに超過を検出
  - **4:00またぎ**: ブロックが4:00をまたぐと翌日ぶんを先に食うので、日ごとに割り振って警告
  - **休憩尺**: `回数 × 周期 > 休憩時間` なら弾く（Ptは収まる回数までしか計上しない）
- オートで焚くライボの総量は**表示のみ**（判定はしない）。理由は下記

## 意図的にやらないこと

- **ライブボーナスの台帳**: 手動ブロックもライボを食うので、オートだけ残量判定を出すと全体としては嘘になる。
  タイムライン全体のライボ収支は別Issueに切る（`worktime` にある計算を寄せる形が筋）。今回はオートの消費量を表示するだけ。
- **オートを休憩の外に置くこと**: 依頼は「休憩時間中のオート」。独立ブロックにすると休憩との二重計上が起きるので持たせない。
- **1日のスタミナ上限**: マイセカイの採取量に上限がある点は `mySekai.ts` と同じ理由で扱わない（残り日数を入力に取っていない）。
