# 周回ラップ計測（/lap）

イベラン中に「1周が実際に何秒かかっているか」をタップで測る道具。
2026-08-20 にイベント214専用の使い捨てページ（`public/wl214/lap/`）として作ったものを、
曲を選べる汎用ツールとして作り直したもの。

## 何を出すためのものか

出したい値は平均ラップそのものより **オーバーヘッド（平均ラップ − 曲長）**。
ロード・マッチング・部屋待ち・支援者交代・リザルト送りの合計が、そのまま自分の環境の実力になる。

サイト全体の見積りは [`src/lib/overhead.ts`](../src/lib/overhead.ts) に既定値（協力54秒／オート33秒／
チャレンジ33秒）を置いている。**このツールはその既定値と自分の実測を並べて出す。**
実測が既定より速い人は他ツールの見積りが保守的すぎるし、遅い人は楽観的すぎる、と分かる。

さらに「1周の獲得Pt」と焚き数を入れると実測の時速Ptが出る。これは編成プロフィールの
`hourlyRate` そのもので、**必要稼働時間計算・周回プランが使う唯一の実測値**（総合力からは計算で出せない）。
その場から編成に取り込めるようにしてある。

## データの持ち方

`marks`（押した時刻の列）と `laps`（区間ごとの周回数）を分けて持つ。

- タップは押し忘れる。押し忘れを「無かったこと」にすると平均が跳ね上がる
- 後から「この区間は2周ぶん」と直せば、**時刻の整合を壊さずに**平均だけ正しくなる
- 除外（`excluded`）は集計から外すだけで、時刻は消さない

## 中断／再開（元の試作からの一番大きな変更）

試作では「再開した瞬間に周回ボタン → 直前を除外」という手順を人間に強いていた。
順番を逆にすると休憩まるごとが1周として混ざり、**平均が数倍に化ける**。しかも数字はもっともらしいので気付けない。

いまは **中断／再開** を明示のボタンにして、再開時にその区間を自動で `excluded` + `breaks` に入れる。
中断中はタップを受け付けず、経過時計も止める（動いていると「測り続けている」と誤解する）。

## 壊れ方への備え

- **長すぎる区間の検出は「曲長の3倍」で見る。** 平均を基準にすると、汚染された平均が閾値ごと押し上げて検出できなくなる
- **平均ラップが曲長を下回ったら警告を出す。** 曲を最後まで聴かずには終わらないので、出たら押し間違いか曲の選び間違い
- **保存に失敗したら黙らない。** 気付かないまま数時間測って全損するのが最悪の事故
- `normalize()` が保存データの形と型を弾く。時刻が昇順でない記録は区間が負になるので丸ごと捨てる
