# 知見の置き場（Knowledge）

プロセカの**計算式・仕様・通例**のうち、公式にもゲーム内にも書かれていないものをまとめる場所。
このサイトのツールが立っている根拠でもある。

## なぜ作るか

この手の知見は、いま**個人の Note・Privatter・X のポスト・Discord のログに散っている**。
どれも正しいことは多いが、

- **前提条件が省かれている**（「テルユアは赤」は1枠かつ巻き込み成功が前提、など）
- **いつの情報か分からない**（仕様変更やスコア改定を跨いでいる）
- **どこまで確かめられているのか分からない**（実測なのか、又聞きなのか）

この3つが抜けたまま伝わるので、正しい知識が**間違った使われ方**をする。
ここが埋めるのはその隙間で、攻略サイトの代わりを作るわけではない。**結論ではなく、前提と根拠と検証状態を書く。**

## 書き方（1ファイル1テーマ）

先頭に必ずこの4行を置く。

```md
# タイトル

- **状態**: 確定 / 有力 / 未検証 / 誤り
- **確かめ方**: 何をもってそう言えるのか（実測・マスタDB・二次情報のどれか）
- **出典**: 誰の・いつの・どこ（URL）
- **最終更新**: YYYY-MM-DD
- **関係するツール**: /ranking など（無ければ「なし」）
```

本文の並びは **結論 → 根拠 → 使いどころ → 未解決** を基本にする。

### 状態の定義

| 状態 | 意味 |
|---|---|
| **確定** | 独立した2つ以上の根拠が一致している（例: マスタDB＋実機計測） |
| **有力** | 根拠は1つだが、反証も見つかっていない |
| **未検証** | 見聞きしただけ。**そのまま計算に使わない** |
| **誤り** | 広まっているが違うと分かったもの。**消さずに残す**（同じ誤解が繰り返し来るため） |

### 守ること

- **他人の調査を自分のものにしない。** 出典を必ず書く。要約するときも書き手を明記する
- **「確定」を安売りしない。** 実測1回は「有力」。再現できて初めて「確定」
- **反証が出たら状態を落とす。** 消すのではなく、いつ何で覆ったかを残す
- **ツールを直したらここも直す。** 逆も同じ。**この2つがずれたら、ずれている方が嘘**
