## 確定した式

### イベントボーナス（実装済み・実編成2つで完全一致）

```
カードごと = キャラ属性ボーナス + レアリティ×マスターランク + カード個別(PU)
合計 = Σ カードごと + WLサポート(手入力)
```

**★ キャラ属性ボーナスは「一致する行を足さない」。** 「キャラ+属性」の行は合算済みの値
（実測: キャラ25 + 属性25 に対して 両方=50）。全部足すと 100 になり倍以上に膨らむ。
**最も具体的に一致する1行だけ**を採る（両方 > キャラ > 属性）。

- 属性の行を持たないイベントがある（実測 207・211）
- VS のキャラは複数ユニットに跨る。`supportUnit` でどの枠かが決まる
- リーダー専用の上乗せはそのカードがリーダーのときだけ
- 対象人数の上限を超えたぶんは効かない（残すのは大きい順）

検証: **315% / 260% とも実機と完全一致**。

### 総合力（実装済み）

```
総合力 = パフォーマンス
       + Σ パラメータ毎 floor(値 × エリア倍率)        ← エリアアイテム
       + Σ パラメータ毎 floor(値 × キャラランク率)     ← CR
       + Σ カード毎     floor(パフォーマンス × ゲート率) ← ゲート
       + Σ カード毎     floor(パフォーマンス × 家具率)   ← 家具（そのキャラのカードだけ）
       + 称号（プレイヤー固有の固定値・編成に1回）

パフォーマンス = 基礎値(レベル) + 特訓 + マスターランク + サイドストーリー + キャンバス
エリア倍率     = ユニット効果 + タイプ効果 + キャラクター効果
                 5枚全員が同じユニット枠 → ユニット効果を2倍
                 5枚全員が同じ属性       → タイプ効果を2倍
```

**★★ ％の計算は float32 でやる。★★**
ゲーム本体が float32 で計算しているので、`rate * 0.01 * base` と書くと実機と1ずれる。
float32 では 0.01 が 0.009999999776… になり、5% は 0.049999998882… になる。
ちょうど割り切れる値で floor が1つ下がる（11540 の5% は 577 ではなく 576）。
**必ず `ratePower()` を通すこと。** これが「CR 5% だと実測より1多い」の正体だった。

**★ 丸めの単位が項目ごとに違う（実測でそう出ている）。**
エリアとCRは**カードごと・パラメータごと**、ゲートと家具は**カードごと・3パラの合計**、
称号は**編成に1回**。同じ％計算なのに違うが、単位を間違えると数十〜数百ずれる。

**★ 全一致は5枚揃って初めて付く。** 1枚・2枚では付かない（実測で確認済み）。

**★ マスターランクの加算は累積。** MR3 なら MR1・2・3 の行を全部足す。

**★ ユニット枠は1つだけ見る。** カードが VS のキャラでも、`supportUnit` があれば
そのユニットの効果しか効かない。エリアもゲートも同じ。

検証: **単体と5枚編成の両方で、全成分が実機と完全一致。**

| | 合計 | パフォ | エリア | CR | ゲート | 称号 |
|---|---|---|---|---|---|---|
| レン(471)単体 | 50,267 | 34,596 | 13,664 | 1,728 | 69 | 210 |
| レオニ5枚・クール染め | 236,756 | 129,838 | 99,968 | 6,483 | 257 | 210 |
| 同・一歌→MEIKO（純ピアプロ） | 215,593 | 129,838 | 78,832 | 6,456 | 257 | 210 |
| 同＋咲希のぬいぐるみ/S | 215,612 | 129,838 | 78,832 | 6,456 | 257 | 210（家具 19） |

- 単体のエリア 13664 は レオニ15% + キュート8.5% + レン16% ＝ 39.5% でぴったり合い、
  VS の 11% を足すと 17469 になって合わない（＝**ユニット枠は1つ**、が確定した根拠）
- 5枚のエリア 99968 は全一致を使わないと 69456 にしかならない（＝**5枚で2倍**の確認）
- 5枚のゲート 257 は、**カードごとに floor** して 74+65+61+39+18。編成の合計に
  1回だけ掛けると 259 になって合わない。咲希が 19994×0.2%＝39.988 で
  40 の直前に落ちるのが効いている

**★ 3件目は対照実験として質が高い。** 一歌(id 1)と MEIKO(id 101)はどちらも
1★Lv20/MR5/前後編読了で**パフォーマンスが 9225 で完全に同じ**なので、
動く変数がユニット枠だけになる。これ1回で4つ確定した:

1. 純ピアプロのカードには **VIRTUAL SINGER の +11% が乗る**
   （supportUnit 付きのレンには乗らなかったのと対）
2. **全一致はユニットとタイプで独立に判定される。** ピアプロが1枚混ざって
   ユニットの全一致は消えたが、5枚とも cool なのでタイプの全一致は残った
3. 純ピアプロのカードのゲートは**全ゲートのうち一番高いもの**（レオニ Lv2 の 0.2%）。
   ゲートが 257 のまま動かないのが証拠（効かないなら 239 に落ちる）
4. **キャラクターランク47 の 4.7%** が効く（上限50に達していないレートの初実測）

**★ 全一致ぶんは効果一覧に出ていないが、マスタ上は必ず通常の2倍**（ユニット・タイプ）。
キャラのアイテムは全一致でも増えない。配信データの全行でそうなっていることを
`power.real.test.ts` が毎回確認しているので、`areaRatesFromEffects()` で 2 倍にしている。
おかげで**入力はゲーム画面の数字をそのまま写すだけで済む**。

- サイドストーリー: 前編+250 / 後編+600（1パラメータあたり）。4★読了で総合力+2,550/枚。
  **入れ忘れると1編成で1万以上ずれる**
- キャンバス: 1枚ごと（4★ +1,500）。レアリティで額が違う
- キャラランク: 47 なら 4.7%（実測）。**CR50 で上限5%**、それ以上は伸びない
- ゲート: `mysekaiGateLevels` に Lv1=0.1% 〜 Lv40=4%。率は5基とも同じ。
  **ゲートは5基のみでピアプロには無い**ので、純ピアプロのカードは
  **全ゲートのうち一番高いもの**を採る（実測）。
  ユニット枠を持つカードはそのユニットのゲートだけを見る

## 実測で分かった細かいこと

### イベントボーナスは表示が切り捨て

レオニ5枚・クール染めの編成で、ゲーム内のカードごとの表示は
**50 / 30 / 25 / 26 / 25.5** なのに、合計の表示は **156%**（156.5% ではない）。
`eventBonus.ts` の計算値は 156.5% で、**カードごとの値は表示と完全に一致している**。

→ 内部は小数を持っていて、**合計の表示だけ切り捨てている**。
比較のときは小数のまま使い、画面に出すときにどうするかは別に決める
（ゲームと同じ 156% にするか、正確に 156.5% と出すか）。

### 家具ボーナスの上げ方と単位

普通の家具をいくら作っても上がらない。**ボーナスを持つのは「◯◯のぬいぐるみ」と
「◯◯のダイヤモンドオブジェ」だけ**（1499個中525個）。サイズで率が決まり、
**置いたキャラのカードにだけ**乗る（編成全体ではない）。

| サイズ | マスタの bonusRate | 実際の率 |
|---|---|---|
| S | 1 | **+0.1%** |
| M | 3 | +0.3% |
| L | 6 | +0.6% |

**★★ マスタの 1/3/6 は % ではなく 0.1% 単位。★★**
実測: 咲希のぬいぐるみ/S を1個置いたら、咲希のカード合計 19994 に対して **+19**。
1% なら 199 になる。ここを % として扱うと家具ボーナスが10倍に膨らむ。
（先駆者の実装が `×0.001` を使っていたのはこのため。当時は理由が分からなかった）

`mysekaiFixtures.mysekaiFixtureGameCharacterGroupPerformanceBonusId` →
`mysekaiFixtureGameCharacterGroupPerformanceBonuses` → `mysekaiFixtureGameCharacterGroups`
と辿るとキャラと率が引ける。1キャラあたりの理論上限は 60〜70（＝**6〜7%**）。
`PlayerState.fixtureRates` は **% で受ける**ので、S 1個なら `0.1`。

### 「351 vs 350」の正体

前の引き継ぎに残っていた「ゲートの丸めが編成1（5枚）だけ 351 vs 350」は**解決済み**。
別の5枚編成（レオニ・クール染め）で 257 が完全に一致した。原因は丸め方ではなく、
**カードごとのパフォーマンスの内訳を取り違えていたこと**だったと思われる
（特訓やマスターランクの入力が1枚ぶんずれると、合計は合っていてもカード単位の
floor が変わってゲートだけ1ずれる）。

## このツールの存在意義（見失わないこと）

**「ボーナスを5%落として総合力を盛った方が、最終的なイベントPtで勝つ」を出せること。**

ゲーム内の「おまかせ編成」はボーナスしか見ないので、そこは絶対に埋まらない穴。
逆に言うと、**ボーナス最大化だけでは差別化にならない**（おまかせで足りる）。

スコア→イベントPt の式は**ランキングとアナライザーに既にあってテスト済み**なので、
比較機能は主に配線で済む。

## 検証の作法（効いたやり方）

- **正解は Nori の実機の数字**。モデルレビューより実測が強い
- **変数を1つずつ動かす**。単体編成 → 2枚 → 5枚、ゲートのレベルを1上げる、という
  差分の取り方で全部の式が割れた。同じ形の編成をいくら集めても分からない
- **未入力を0と混同しない**。MR の記載が無い編成を0として計算し、5%ズレの原因を
  「データと実機の食い違い」だと疑って仮説を3つ立てたが、ただの入力漏れだった
- **合った例だけ集めない**。実測が合ったあとに Fable-B で「それでも間違っている編成が
  あるはずだ」と探させる予定（まだ未実施）
- **先に先駆者の実装を読むのがいちばん速かった**。float32 の件は実測の差分からは
  「4.999999% なら合う」までしか出ず、理由に辿り着けなかった。他人のコードに答えが
  書いてあった。自分で式を割る前に GitHub を探す
- **同じ強さのカードを差し替えると対照実験になる**。一歌と MEIKO はどちらも
  1★Lv20 でパフォーマンスが 9225 で完全に同じだったので、1枚入れ替えるだけで
  「ユニット枠だけが違う編成」が作れた。1回の実測で4つ確定した
- **仮説を並べて実測にぶつける**。「エリアはユニット枠を1つ見るのか両方見るのか」は、
  候補を3つ計算して 13664 / 12280 / 17469 と並べたら一発で決まった。
  1つの仮説を検証しようとするより、候補を全部出して実測と照合する方が速い
- **実測から編成を逆算できる**。カードの基礎値は配信データにあるので、
  「パフォーマンス 34596」から総当たりでカードと育成状態を特定できた（レン id 471）。
  実測のメモにカード名しか無くても、後から検算に使える
