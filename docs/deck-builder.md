## 確定した式

### イベントボーナス（実装済み・実編成2つで完全一致）

```
カードごと = キャラ属性ボーナス + レアリティ×マスターランク + カード個別(PU)
合計 = Σ カードごと + WLサポート(手入力)
```

**★ キャラ属性ボーナスは「一致する行を足さない」。** 「キャラ+属性」の行は合算済みの値
（実測: キャラ25 + 属性25 に対して 両方=50）。全部足すと 100 になり倍以上に膨らむ。
**最も具体的に一致する1行だけ**を採る（両方 > キャラ > 属性）。

- 属性の行を持たないイベントがある（実測 207・211）
- VS のキャラは複数ユニットに跨る。`supportUnit` でどの枠かが決まる
- リーダー専用の上乗せはそのカードがリーダーのときだけ
- 対象人数の上限を超えたぶんは効かない（残すのは大きい順）

検証: **315% / 260% とも実機と完全一致**。

### 総合力（未実装・式は判明）

```
総合力 = パフォーマンス
       + Σ パラメータ毎 floor(値 × エリア倍率)        ← エリアアイテム
       + Σ パラメータ毎 floor(値 × キャラランク率)     ← CR
       + Σ カード毎     floor(パフォーマンス × ゲート率) ← ゲート
       + 称号（プレイヤー固有の固定値）
       + 家具（キャラ紐付き・1〜6%・上限100%）

パフォーマンス = 基礎値(レベル) + 特訓 + マスターランク + サイドストーリー + キャンバス
エリア倍率     = ユニット効果 + タイプ効果 + キャラクター効果
                 5枚全員が同じユニット枠 → ユニット効果を2倍
                 5枚全員が同じ属性       → タイプ効果を2倍
```

**★ 丸めの単位が項目ごとに違う（実測でそう出ている）。**
エリアとCRは**パラメータごと**、ゲートは**カードごと**。同じ％計算なのに違うが、
単位を間違えると数十〜数百ずれる。

**★ 全一致は5枚揃って初めて付く。** 1枚・2枚では付かない（実測で確認済み）。

- サイドストーリー: 前編+250 / 後編+600（1パラメータあたり）。4★読了で総合力+2,550/枚。
  **入れ忘れると1編成で1万以上ずれる**
- キャンバス: 1枚ごと（4★ +1,500）。レアリティで額が違う
- キャラランク: **CR50 で上限5%**。それ以上は伸びない
- ゲート: `mysekaiGateLevels` に Lv1=0.1% 〜 Lv40=4%。**ゲートは5基のみで VS には無い**。
  カードのユニット枠ごとに別のゲートを見る

検証: パフォーマンスは**4編成で完全一致**、エリアアイテムは編成1で完全一致（131,104）。

## このツールの存在意義（見失わないこと）

**「ボーナスを5%落として総合力を盛った方が、最終的なイベントPtで勝つ」を出せること。**

ゲーム内の「おまかせ編成」はボーナスしか見ないので、そこは絶対に埋まらない穴。
逆に言うと、**ボーナス最大化だけでは差別化にならない**（おまかせで足りる）。

スコア→イベントPt の式は**ランキングとアナライザーに既にあってテスト済み**なので、
比較機能は主に配線で済む。

## 検証の作法（効いたやり方）

- **正解は Nori の実機の数字**。モデルレビューより実測が強い
- **変数を1つずつ動かす**。単体編成 → 2枚 → 5枚、ゲートのレベルを1上げる、という
  差分の取り方で全部の式が割れた。同じ形の編成をいくら集めても分からない
- **未入力を0と混同しない**。MR の記載が無い編成を0として計算し、5%ズレの原因を
  「データと実機の食い違い」だと疑って仮説を3つ立てたが、ただの入力漏れだった
- **合った例だけ集めない**。実測が合ったあとに Fable-B で「それでも間違っている編成が
  あるはずだ」と探させる予定（まだ未実施）
