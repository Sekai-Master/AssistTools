# モードAを「現編成N回 ＋ 端数1回（編成選択）」に再構成する ブリーフ

作成: 2026-07-25 / 前段: `point-adjust-modeA-choices-brief.md`（コミット 06813cc で実装済み）
状態: **ワークフロー未起動**（Nori のGO待ち）。方向は合意済み。

## 背景と方向転換

前段（06813cc）でモードAを「複数候補を提示→選択」にし、397%問題（非現実的な組み替えの
自動採択）は解消した。しかしその実装は候補ごとに「全プレイを別ボーナスで組む」プランを
丸ごと並べる形で、複数回プランは編成を全回組み替える前提が残っていた。

Nori の洞察と実測（2026-07-25）で、より良い構造が確定した:

> **登録している編成（現ボーナス）でN回 ＋ 選んだ端数編成で1回、の2種類あれば大半の残額は作れる。**

実測（base100・現ボーナス990%）:
- 現編成の1回到達値: 1,090〜59,115（612通り）
- 端数編成（ボーナス0〜990%可変）の1回到達値: 100〜59,115（7,386通り）
- **「現編成 N回 ＋ 端数編成 1回」で残額 1〜100,000 のカバー率 99.90%**（作れないのは 1〜99 の 99個のみ）

### なぜこの形が正しいか（397問題が構造的に消える）

- 397%問題の根は「全プレイを非現実的なボーナスで組み直せ」だった。
- この形なら **組み替えるのは端数の1回だけ**。メインの N回は現編成のまま（いじらない）。
- 端数は小さい値でよいので、端数用編成は「ボーナスを少しゆるめた編成を1つ用意する」程度。
  5回6回と組み直す必要がない。

## 設計方針

**モードA = 「現編成でN回（バルク・自動）＋ 端数編成で1回（ユーザーが選ぶ）」** に再構成する。

- バルク: 現在ボーナス固定で、残額を端数編成1回でカバーできる所まで N回（N≥0）寄せる。
  N は自動決定。現編成なので編成をいじらない。
- 端数: 残りを1回で埋める。この1回の編成（ボーナス）を **ユーザーが候補から選ぶ**。
  候補は「現ボーナスからの下げ幅が小さい順」に並べる（397% 級は下に沈む）。
- 「1回でピッタリ（N=0）」のケースは端数のみで表現（現編成そのままで1回＝下げ幅0の候補）。

### 現行実装（06813cc）との差分

- 現行 `modeAChoices.ts` は keep（現ボーナス維持プラン）と rebuild（組み替えプラン）を
  丸ごと並べる。これを **「バルク（現編成N回・固定）＋ 端数候補（選択）」** の構造に変える。
- 端数候補 = 「残額 − N×(現編成1回値) を1回で埋める編成」の集合。各候補は端数のボーナス・
  LB・スコア帯・獲得Pt を持つ。並びは端数ボーナスの下げ幅が小さい順。
- N（バルク回数）と バルクの1回値（現編成のどのスコア帯/LBか）をどう決めるかは設計者が
  詰める。候補ごとに N が変わりうる（端数値によってバルクで寄せる量が変わる）点に注意。

## 計算（探索本体は無改変）

- 現編成 N回のバルク値: 現ボーナス固定・LB×スコアの到達値（前段 `buildKeepBonusTable`
  /`planModeAKeepMulti` が現ボーナス固定の複数回を既に解ける。これを流用/拡張）。
- 端数1回の候補: 残り = 残額 − N×バルク値 を1回で作る (ボーナス, LB, スコア) の集合。
  ボーナス可変1回の到達値は既存の掃引（`liveAdjust.ts` 5.2）や `buildBonusSweepTable` が
  持つ。**探索ループ・frontier・掃引は無改変**。呼び出しと詰め替えで実現する。
- 「N回 + 端数1回」の分解は、現行 frontier の「n-1回バルク + 端数1回」と同型なので、
  探索本体を変えずに **バルク側を現編成固定に縛る** ことで得られる（前段の buildKeepBonusTable
  の考え方の延長）。設計者は「バルク＝現編成固定、端数＝ボーナス可変」で候補列を作る具体を決める。

## UI

- モードA = 「現編成で N回」の表示（固定・編成そのまま）＋「端数の1回」の編成選択。
- 端数編成の候補リスト（下げ幅の小さい順）から選ぶ。earn 風の選択（前段 ModeAChoicePanel を
  流用/改修）。既定選択は先頭（下げ幅最小＝現編成に一番近い端数）。
- 統合画像: バルク行（現編成 N回・目標ボーナス表記なし）＋ 端数行（選んだ編成・目標ボーナス表記）。
  前段の canvas 分岐（multi/sweep）をそのまま使えるはず。
- 「組める端数編成を選んでください」の注記（ツールは組める判定をしない旨）。
- N=0（端数のみで着地）のときはバルク行を出さない（スキップ＝詰め）。

## 勝利条件

1. モードA が「現編成 N回（自動）＋ 端数1回（選択）」で表示され、端数編成を選べる。
2. 端数候補が「下げ幅の小さい順」に並び、397% 級が先頭に来ない。
3. 組み替えは端数1回分だけ（バルクは現編成のまま）であることが画像・表示で伝わる。
4. 残額 100 以上で着地できる（1〜99 は端数の最小値未満で原理的に不可＝正しく NG 案内）。
5. 既存の計算結果（厳密一致・回数最小性）を1ptも壊さない。
