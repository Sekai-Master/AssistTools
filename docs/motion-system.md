# 画面遷移の演出とモーション設定

ニューモーフィズムの「素材から押し出された／へこんだ」という物理メタファーを、
コンポーネント単位（`.neu-tactile` の押下）から**画面遷移そのもの**へ拡張した仕組み。

実装は `src/motion/` に集約。関連: [porting/design.md](porting/design.md)（不可侵ライン）

---

## 何が起きるか

ページを切り替えると、

1. **沈む** — ブロックごとに色が抜け、輪郭がぼやけ、消える。同時に影が潰れて画面全体が `#f0f0f0` の平らな面に還る
2. **無地** — 素材だけの状態。ここで新しいページのチャンク到着を待つ
3. **浮く** — ぼやけた塊がブロックごとに像を結び、最後に色が戻る。影は全体で育ち続ける

動いている層は2つあり、**別々の時間で走る**。

| 層 | 対象 | 振る舞い |
|---|---|---|
| **素材** | `html` の `--neu-lift` | 一枚の面として沈み、一枚の面として戻る。影を持つ全要素が同時に潰れる。**カスケードしない** |
| **ブロック** | `[data-div]` の opacity / blur / saturate | 色 → 輪郭 → 存在 の順に溶け、逆順で戻る。**こちらだけが順番にずれる** |

素材が一斉に動くのは、ニューモーフィズムが「1つの光源に照らされた1枚の素材」を
前提にしているから。面ごとに影の量が違う瞬間があると、光源が複数あるように見えて
素材の嘘がばれる。一方ブロックは素材の上に載っている造形なので、順番に出入りしてよい。

### 波の向き（意図的な非対称）

沈みは**下から上へ**（`1 - t`）、浮上は**上から下へ**（`t`）。
波が上がってから下りてくる1つの息継ぎになる。

視線はふつう上端（ヘッダー/押したリンク）にあるので、**最後に消えた場所から
最初に戻ってくる**ことになり、無地を挟んでも視覚的に連続する。
両方とも上からにすると、視線のある上端が最も長く空白になる。

### 実測したフレーム（Chromium・`/` → `/evc`）

| 時刻 | 何が起きているか |
|---|---|
| 62ms | 最下段のブロックだけが動き出す（sat 0.68 / opacity 0.60）。上段は無傷 |
| 184ms | 先頭ブロックは **sat 0.81 なのに opacity は 1.00** — 色が先に抜けている |
| 310ms | 下半分は消え終わり、上半分がまだ 0.87 で残っている |
| 440ms | 無地。`--neu-lift` = 0 |
| 638ms | 先頭ブロックが opacity 0.95 / blur 2.1px。**sat はまだ 0.05**（灰色の浮き彫り） |
| 903ms | 先頭は sat 1.0 に到達。最下段はまだ blur 3.5px |
| 1120ms | 完了 |

「色が抜けてから消える／像を結んでから色が戻る」がこの演出の核。
単なるクロスフェードでも、単なるスタッガードフェードでもない。

## 段階（設定 `/settings`）

| 設定 | 実際の挙動 | 出はじめ | 出そろい |
|---|---|---|---|
| **自動**（既定） | OS が視差軽減なら「オフ」、それ以外は「控えめ」 | — | — |
| **オフ** | 演出なし。切り替えは即時 | 0ms | 0ms |
| **控えめ** | 沈まない。新しいページだけが影を持って浮き上がる | 0ms | 180ms |
| **リッチ** | 沈む → 無地 → 浮く（ブロック単位のカスケード付き） | 440ms | 1120ms |

**段階の切り方は「秒数を短くする」ではなく「構造を外す」。**
「控えめ」は無地に戻る間もカスケードもぼかしも持たない。体感待ち時間の増加がゼロで、
`box-shadow` の再描画パスが遷移あたり2回から1回に半減する。単に duration を縮めた版ではない。

### 既定はなぜ「控えめ」か（2026-08-01 変更）

以前は auto が端末クラスで分岐し、PC では既定でリッチだった。リッチの尺が
1秒を超える見世物になったので、**黙って全員に出してよい性格のものではなくなった**。
auto は全端末で控えめに解決し、リッチは設定画面で明示的に選んだ人にだけ出す。

端末クラス（`touchOnly`）の検出は残してあるが、解決には使わず
「この端末ではリッチは重いかもしれない」という**注記の出し分け**にだけ使う。
フレーム時間を実測して勝手に降格させることは相変わらずしない
（明示的に選んだ設定を裏で書き換えると設定 UI の意味が壊れる）。

### 予算は2本立て

合計の長さで縛ると、この設計は成立しない。リッチの後半は
「もう読める画面の上でカスケードが完了していく時間」だから。

- `MOTION_FIRST_PAINT_BUDGET_MS = 500` — **操作してから最初の中身が出はじめるまで**。
  ここが体感の応答速度。リッチは 440ms
- `MOTION_TOTAL_BUDGET_MS = 1200` — 出そろうまで。超えると「まだ終わらないのか」に変わる。
  リッチは 1120ms

`plan.test.ts` が全レベルで両方を検証しているので、振り付けを伸ばすと CI が落ちる。

## reduced-motion の優先順位（意図的な非対称）

| 対象 | 優先されるもの |
|---|---|
| 遷移演出（＝装飾） | **設定画面での明示選択が OS より優先** |
| 押下フィードバック（`.neu-tactile` / `.neu-cta`） | OS が絶対 |
| ローディングインジケータ（＝機能フィードバック） | OS が絶対 |

既定は「自動」なので、設定画面に一度も来ない人には OS の意思が 100% 通る
（WCAG 2.3.3 の「動きを無効化する手段」を既定で満たす）。明示的に選んだときだけ
それが勝つ — OS 設定はグローバルな既定で、この画面での選択はより新しく具体的な
意思表示だから。**黙って上書きはしない**（OS 側が reduce のとき設定画面に注記を出す）。

なおこの演出は translate / scale / 回転 / パララックスを一切含まない（影と不透明度だけ）ので、
上書きされても前庭系のトリガーにならない。

## 設計判断の記録

### `--neu-lift` は必ず `html` 上で動かす

影の量を `--neu-lift`（0 = 素材と面一 / 1 = 通常）という 1 変数に還元し、
`@theme` の影トークン4本を `calc(Npx * var(--neu-lift, 1))` にしてある。

**これを子孫要素で動かしてはいけない。** 実ブラウザ（Chromium）で検証した結果:

| `--neu-lift: 0` を置く場所 | `.neu-panel`（コンポーネントクラス） | `.shadow-neu-inset`（ユーティリティ） |
|---|---|---|
| `html` | 潰れる ✅ | 潰れる ✅ |
| 子孫（`.stage`） | **5px のまま残る** ❌ | 潰れる |

カスタムプロパティの `var()` は「宣言された要素」で computed-value 時に置換される。
`@theme` が出す `--shadow-neu` は `:root, :host` に宣言されるので、`:root` の時点で
`--neu-lift` が焼き付いた文字列が確定し、子孫はそれを継承するだけになる。
一方 Tailwind のユーティリティは要素側で `--tw-shadow` を宣言するので追随する。

結果、子孫で動かすと「**パネルの影は据え置きで、中のボタンだけ平ら**」という
狙いの真逆の絵になる。`html` 上なら `:root` の `--shadow-neu` 自体が再計算され、
コンポーネントクラスとユーティリティの両系統が同時に沈む。

### ブロックの分け方をページ側に要求しない

カスケードの順番は `divisions.ts` が遷移のたびに DOM を1回歩いて決める。
全ツールに `data-` 属性を撒く案は採らなかった — 新しいページを足すたびに
演出が抜け落ちる事故が起きるため。

規則はひとつ、**「自分の見た目（影・背景・枠・直下のテキスト）を持たない箱は割る、
持つ箱はそこで止める」**。ニューモーフィズムでは "浮いている箱" がそのまま意味の
単位なので、影の有無がブロック境界のよい近似になる。結果として

- `ToolPage` → 見出しバナー ＋ `Panel` ごと
- `Hub` → 見出し・リード・小見出し ＋ **カード1枚ずつ**

に自然に割れる。中身が1つしか無い入れ物（`<Link className="block">` など）は
外皮として剥がすので、カードは `Link` ではなく `.neu-panel` 本体が選ばれる。
剥がすときに数えるのは**描画されている子だけ**。`hidden lg:block` と `lg:hidden` が
並ぶ2カラムは実際にはどちらか片方しか出ていないので、生の `children` で数えると
剥がし損ねてページ全体が1ブロックに潰れる。

上限（16個）を超えたら**捨てずに1段粗く割り直す**。捨てると印の付かない中身が
居残り、無地へ切り替わる瞬間にだけ消える（ポップする）。

### 画面外のブロックにはカスケードの尺を配らない

長いページで下まで順に遅延させると、見えている数ブロックが一瞬で終わって
残りの尺が画面外で浪費される。`--div-t`（0..1）は**画面内の並びにだけ**張り、
上にあるものは 0、下にあるものは 1 に丸める。
ぼかしも画面内（`data-div="near"`）のブロックにしか掛けない
＝ `filter` の面積を常に1画面ぶんに抑える。

### 印を付けたら1回だけスタイル計算を強制する

浮上では、印を付けた直後に `data-stage` が `rise` へ変わる。同じタスク内の2回の
DOM 変更はまとめて1回しか計算されないので、transition の**開始値が確定せず
カスケードが丸ごと効かない**（全ブロックが一斉にパッと出る）。
`markDivisions` → `html[data-divs]` を立てる → `flushStyles()` の順で、
無地の状態＝開始値をブラウザに確定させる。順番を入れ替えると静かに壊れる。
沈みでは開始値が既定値のままなので呼ばない（余計なリフローを踏まない）。

### `filter` は遷移中だけ宣言する

`blur` と `saturate` は1つの `filter` プロパティなので、直接書くと色と輪郭を
別々の時間で動かせない。量を `@property` 済みのカスタムプロパティ
（`--div-blur` / `--div-sat`）へ逃がし、`filter: blur(var(--div-blur)) saturate(var(--div-sat))`
と組むことで2チャンネルに分けている（`--neu-lift` と同じ手口）。

**この `filter` を常設してはいけない。** `filter` は `position: fixed` の包含ブロックを
作るので、ステージ内の `fixed`（`TweetGenerator` のモバイルバー、ポータルを使っていない
モーダル）が要素基準の座標へ飛ぶ。`:not([data-stage="idle"])` で囲ってあるので
静止時の影響はゼロ。
遷移中にモーダルが開いている場合だけは避けられないので、モーダル側が `data-overlay`
を出し、CSS が `:has([data-overlay])` でカスケードを降ろしてステージごとのフェードに戻す。

### 遷移演出に `transform` を使わない

`.stage` に `transform` が乗ると `position: fixed` の包含ブロックが `.stage` へ
切り替わり、以下が壊れる:

- `TweetGenerator` のモバイル常設アクションバー（`fixed inset-x-0 bottom-0`）
- `SongSearchModal` / `PlanListModal`（`fixed inset-0`。`createPortal` を使っていない）

`opacity` は包含ブロックを変えないので安全。`isolation: isolate` も同じ理由で使わない
（常設のスタッキングコンテキストを作ると、上記モーダル `z-50` が Layout の
`sticky z-40` ヘッダーの下に潜る）。

### 無地の間に浮いていてほしい要素は影をリテラルで書く

無地の間は `--shadow-neu*` が**意図的に** 0 へ潰れている。失敗カードのように
「まさにその場面で見えてほしい」ものにトークンを使うと見えなくなる。`.neu-static` を使う。

### View Transitions API を採用しなかった理由

1. `BrowserRouter` 経路では `<Link viewTransition>` が実質 no-op
   （`startViewTransition` に繋がるのは `RouterProvider` の setState 経路だけ）
2. **VT のスナップショットは静止画なので `box-shadow` を補間できない。**
   この演出の要である「影が消えて素材に沈む」が原理的に opacity フェードにしかならない
3. UA スタイルの `::view-transition-group(*)` が 0.25s を持つため、
   `old(root)` だけ上書きしても `finished` の解決時刻がズレる

### 二重チラつきを構造から消す

全ツールが `React.lazy` + `Suspense` なので、素朴に作ると
「無地 → 読み込み中… → 無地」の二重チラつきになる。

`RouteStage` は描画する location を自前で握り、沈み込み完了時に
`startTransition(() => setShown(target))` する。**既に中身を持つ Suspense 境界への
transition 更新では、React 19 は fallback へ切り替えず前の木を保持したまま待つ**ので、
通常のページ遷移で `PageFallback` は原理的に描画されない。

浮上のトリガーは時間ではなく「新しい木が実際に commit された瞬間」なので、
チャンクが遅ければ無地のまま待つだけで、途中で一度浮いてまた沈むことはない。

残るのはハードリロード／直リンクの初回だけ（境界に前の中身が無いので本物の
fallback が出る）。そこは `.stage-fallback` を「文字なしの無地面 ＋ 450ms 遅れて
文言をフェードイン」にして、速い回線では文言自体が視認されずに終わるようにしてある。

### 演出の「間」をロード時間に変える

`prefetchRoute` は `React.lazy` と**同じ import 関数・同じ Promise** を共有する
（`motion/routes.ts` に集約した理由）。`NAVIGATE` の時点で先読みが走るので、
沈み込みの 130ms がそのままチャンクのロード時間になる。

## 演出ではなく「機能」として全レベルで動くもの

「オフ」でも動く。これらは装飾ではないため。

- スクロール復元（react-router v7 は復元しない）
- フォーカスをステージ先頭へ移す
- `aria-live` での遷移先読み上げ
- チャンクの先読み
- チャンク読み込み失敗の検知

### スクロール復元の勘所

- 退避は**旧ページが見えている間**に。無地の最中は既に新しい木が commit されていて
  `scrollY` が新ページの高さでクランプされうるので、そこで保存すると旧ページの記憶を壊す
- 復元は**新しい木がレイアウト済み・かつ画面上は無地**の一瞬に。位置が飛ぶ様子が見えない
- 副作用の順序は `restoreScroll` → `focusStage` → `announce` で固定（`machine.test.ts`）。
  逆にするとフォーカス移動に伴うブラウザのスクロールが復元位置を上書きする
- `bootstrapMotion()` で `history.scrollRestoration = "manual"` にしてある
  （ブラウザ既定の復元と二重にかからないように）

## チャンク読み込み失敗

`netlify.toml` は SPA フォールバック（未知パスを index.html へ 200 で返す）なので、
タブを開いたまま再デプロイされると、古いハッシュのチャンク要求に **JS ではなく HTML が 200 で返り**
`import()` が MIME エラーで reject する（Vite + SPA ホスティングの定番事故）。

演出を被せた状態でこれが起きると「無地のまま永久に待つ」になり、失敗が成功と
見分けられなくなる。三重の網で拾う:

1. 先読みの reject → `FAILED`（通常のページ遷移）
2. `FAILSAFE`（10s）→ `READY` も `FAILED` も来ないまま固まった場合
3. `RouteErrorBoundary` → 初回ディープリンクなど先読みを経由しない経路

## 共有要素の変形（一覧 → ツール）

ハブのカードを押すと、**そのカードだけが素材から持ち上がり**、他が溶けているあいだ
浮いたまま残り、行き先ページの見出しバナーの位置・形へ飛んで着地する。
「一覧から選ぶ → その画面になる」を、切り替えではなく1つの連続した動きとして読ませる。

実装は `src/motion/morph.ts`。

### 対応づけはキーでやる。押されたリンクを見張らない

ページ側は `data-morph="<キー>"` を置くだけ。遷移の前後で**同じキーを持つ要素が
両方に居たとき**だけ変形が走る。

| 場所 | キー |
|---|---|
| ハブのカード | `tool:<ツールid>` |
| `ToolPage` の見出し（`morphKey` prop） | 同じ値 |

こうすると**向きが自動で決まる**。戻るときは「見出し → カード」に逆流するだけで、
戻る/進む用のコードが要らない。キーを付け忘れたページは対応が付かないので、
黙ってふつうの遷移になる（壊れない）。

### ステージの外でやる

変形は位置と大きさを動かすので `transform` が要る。ところが `.stage` の中で
`transform` / `filter` を使うと `position: fixed` の包含ブロックを奪ってしまい、
モバイルの常設バーやポータル未使用のモーダルが飛ぶ（上記の制約と同じ）。

そこで**複製を `body` 直下の `#morph-layer`（`position: fixed`）へ出して**動かし、
ステージ本体には一切触らない。複製なので、元ページが差し替わっても飛んでいるものは
影響を受けない。z-index はヘッダー(40)より上・モーダル(50)より下。

### 複製は2枚重ねる。ただし中身も一緒に伸ばす

出発点（カード 317×209）と到着点（見出し 736×52）は中身も比率も違う。
2枚重ねて箱を同じ軌道で動かし、透明度で入れ替える。

**中身は `transform: scale()` で箱に追従させる。** レイアウト（幅・高さ）は本来の
大きさのまま組んで動かさない ── 幅を毎フレーム変えると折り返しが変わって文字が踊る。

★ ここを最初「中身は原寸のまま `overflow` で切るだけ」にしていたが、それだと
**箱だけが大きくなって中身は左上に residual として残る**。伸びているように見えず、
移動が終わって中身が入れ替わって初めて大きさの変化に気づく
＝「移動してから一瞬で伸びた」という読み方になる（Nori 指摘 2026-08-01）。
中身も一緒に伸ばすと、移動と変形が1つの動きとして読める。

実測（`/` → `/bingo`、リッチ）:

| 時刻 | 箱 | 中身の倍率 | 不透明度 (from / to) |
|---|---|---|---|
| 0ms | 317×209 | 1.00 | 1.00 / — |
| 52ms | 324×213 | 1.00 | 1.00 / — （摘まみ上げ） |
| 〜452ms | 324×213 | 1.00 | 1.00 / — （素材が溶けるのを待つ） |
| 519ms | 377×192 | 1.17 / 0.90 | 1.00 / 0.00 |
| 648ms | 634×92 | 1.99 / 0.44 | 1.00 / 0.00 |
| 769ms | 710×62 | 2.24 / 0.30 | 0.10 / 0.90 |
| 1102ms | 736×52 | 2.32 / 0.25 | 0.00 / 1.00 （着地） |

### 入れ替えは真ん中でだけ

中身を引き伸ばすので、**出発点の複製は終盤ほど歪み、到着点の複製は序盤ほど歪む**。
だから「最初は出発点だけ・最後は到着点だけ」を見せ、いちばん歪んでいる真ん中でのみ
2枚を混ぜる（`opacity` だけ尺の 28% 遅らせて短く走らせる）。
ここを端に寄せると、ひしゃげた文字がはっきり見えてしまう。

### 待っているあいだも少し浮かせる

リッチでは行き先が分かるまで 440ms（沈み 350 ＋ 無地 90）待つ。完全に静止させると
「固まった」ように見えるので、持ち上げた瞬間に `scale(1.02)` へ浮かせておき、
飛びながらそれを降ろす ＝ 摘まみ上げて、行き先へ置きにいく、という手つきになる。

### 飛んでいるものは沈まない

`--neu-lift` は `html` で動かしているのでレイヤーの複製にも継承される。何もしないと
「持ち上げたカードの影だけ道中で消える」ことになるので、`.morph-box` で `1` に固定する。
**周りが素材へ還るあいだ、選ばれたものだけが浮いたまま残る** ＝ 演出の主語がどれかを影で示す。

### 押下で「どれ」かを指名する

一覧には同じ印のカードが何枚も並ぶので、採寸だけでは出発点が決まらない。
`RouteStage` の `onClickCapture` で押された要素を指名しておく。

印が**1つしか無いページ**（ツールページの見出し）では指名が無くても決まるので、
ブラウザバックでもそのまま逆再生になる。

★ 指名は押された点から**上にも下にも**探す。ハブのカードはリンクの*子*なので、
キーボードの Enter やリンク自体の押下では `target` がリンクになり、`closest` だけでは届かない。

### `transition-property` は TS 側が正本

`transition-duration` は値が足りないと先頭から循環して割り当てられる。
CSS に property を書いて TS から duration だけ渡すと、「`left` と `height` だけ
違う速さで動いて箱が歪む」という壊れ方をする。並びと個数を `morph.ts` の `MOVED` で
1箇所から作り、CSS には緩急だけ置く。`morph.test.ts` が個数の一致を検証している。

### 段階との関係

| 設定 | 変形 |
|---|---|
| オフ | しない |
| 控えめ | **する**（320ms） |
| リッチ | する（520ms） |

カスケードが「装飾」なのに対し、変形は**「押したものと開いた画面が同じものだ」という
説明**なので、既定の控えめでも動かす。オフだけが 0。

## 構成

```
src/motion/
  plan.ts          設定 × OS → MotionPlan（純関数。duration・blur 量の正本）
  machine.ts       遷移の有限状態機械（純粋リデューサ。effects をデータで返す）
  useRouteStage.ts 唯一の不純な層。effects を setTimeout/startTransition/scrollTo/focus に翻訳
  divisions.ts     ページをブロックに割って順番(--div-t)を書き込む。DOM を触る唯一の純ロジック
  routes.ts        lazy と先読みが同じ Promise を共有する正本
  settingsStore.ts useSyncExternalStore + localStorage（planStorage.ts と同じ流儀）
  scrollMemory.ts  location.key ごとのスクロール記憶
  environment.ts / bootstrap.ts / stageContext.ts
  motion.css       振り付け（ms も px も書かない。html の --stage-* から受け取る）
```

`machine.ts` は DOM もタイマーも React も router も知らない。だから「遅いチャンク」
「連打」「戻る」「失敗」の経路をブラウザ無しで全部テストできる。

duration の正本は TS 側（`MotionPlan`）で、`html` の `--stage-sink` / `--stage-rise` に
流し込む。CSS には ms を1つも書かない（二重管理をしない）。

## 未確定・オーナー判断待ち

- **ヘッダーも一緒に沈むが、これでよいか。** `--neu-lift` を `html` で動かす結果、
  ヘッダーのロゴやメニュー項目の影も潰れる。ヘッダー自身のガラス帯と枠線は残るので
  「土台のバーは残ったまま、素材だけが一斉に静まる」絵になる。
  尺が伸びた（リッチで最大 1.1 秒）ぶん、以前より目につきやすくなっている。
- **戻る／進む（POP）にも同じ尺を課してよいか。** ブラウザバックは「無料」だと
  期待されている操作なので、`sinkMs` を半分にする非対称もありうる。
- **リッチでの浮上中、まだ出ていないブロックにも Tab で入れる。** ブロック単位の
  遅延（最大 300ms）のあいだ opacity 0 の要素にフォーカスできる。浮上開始時に
  フォーカスをステージ先頭へ移しているので実害は小さいと判断して放置してある。
  ブロック単位に `inert` を出し入れすれば消せるが、機構が重くなる。
- **失敗カードの文言。** 「サイトが更新された可能性があります。再読み込みしてください」。
