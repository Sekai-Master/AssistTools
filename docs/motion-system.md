# 画面遷移の演出とモーション設定

ニューモーフィズムの「素材から押し出された／へこんだ」という物理メタファーを、
コンポーネント単位（`.neu-tactile` の押下）から**画面遷移そのもの**へ拡張した仕組み。

実装は `src/motion/` に集約。関連: [porting/design.md](porting/design.md)（不可侵ライン）

---

## 何が起きるか

ページを切り替えると、

1. **沈む** — 影が潰れて画面全体が `#f0f0f0` の平らな面に還る
2. **無地** — 素材だけの状態。ここで新しいページのチャンク到着を待つ
3. **浮く** — 影が育ちながらページが表面へ押し出されてくる

沈み・浮きのどちらも**主役は影であって不透明度ではない**。振り付けを非対称にしてある。

| 向き | 実測したフレーム |
|---|---|
| 沈み | `--neu-lift` が 1→0.62→0.13 と落ちる間、中身の不透明度は **1 のまま**。潰れきってから 0.93→0.69→0 と溶ける |
| 浮上 | `--neu-lift` が 0→0.32→0.58→0.76 と育つ途中、不透明度は **lift=0.958 の時点で既に 1** に到達 |

つまり沈みでは「先に浮きが消えて面一になり、そのあと平らな中身が消える」、
浮上では「中身が読めるようになった後も影が育ち続けて押し出される」。
単なるクロスフェードとの違いはここにある。

## 段階（設定 `/settings`）

| 設定 | 実際の挙動 | 合計 |
|---|---|---|
| **自動**（既定） | OS の `prefers-reduced-motion` に追随。オフなら「リッチ」 | — |
| **オフ** | 演出なし。切り替えは即時 | 0ms |
| **控えめ** | 沈まない。新しいページだけが影を持って浮き上がる | 160ms |
| **リッチ** | 沈む → 無地 → 浮く | 380ms |

**段階の切り方は「秒数を短くする」ではなく「構造を外す」。**
「控えめ」は無地に戻る間そのものを持たないので、体感待ち時間の増加がゼロになる。
影の語彙（この製品固有の表現）は保ったまま、`box-shadow` の再描画パスが遷移あたり
2回から1回に半減する。単に duration を縮めた版ではない。

体感速度の予算は `MOTION_BUDGET_MS = 400`。`plan.test.ts` が全レベルで
`sink + minBlank + rise <= 400` を検証しているので、振り付けを伸ばすと CI が落ちる。

## reduced-motion の優先順位（意図的な非対称）

| 対象 | 優先されるもの |
|---|---|
| 遷移演出（＝装飾） | **設定画面での明示選択が OS より優先** |
| 押下フィードバック（`.neu-tactile` / `.neu-cta`） | OS が絶対 |
| ローディングインジケータ（＝機能フィードバック） | OS が絶対 |

既定は「自動」なので、設定画面に一度も来ない人には OS の意思が 100% 通る
（WCAG 2.3.3 の「動きを無効化する手段」を既定で満たす）。明示的に選んだときだけ
それが勝つ — OS 設定はグローバルな既定で、この画面での選択はより新しく具体的な
意思表示だから。**黙って上書きはしない**（OS 側が reduce のとき設定画面に注記を出す）。

なおこの演出は translate / scale / 回転 / パララックスを一切含まない（影と不透明度だけ）ので、
上書きされても前庭系のトリガーにならない。

## 設計判断の記録

### `--neu-lift` は必ず `html` 上で動かす

影の量を `--neu-lift`（0 = 素材と面一 / 1 = 通常）という 1 変数に還元し、
`@theme` の影トークン4本を `calc(Npx * var(--neu-lift, 1))` にしてある。

**これを子孫要素で動かしてはいけない。** 実ブラウザ（Chromium）で検証した結果:

| `--neu-lift: 0` を置く場所 | `.neu-panel`（コンポーネントクラス） | `.shadow-neu-inset`（ユーティリティ） |
|---|---|---|
| `html` | 潰れる ✅ | 潰れる ✅ |
| 子孫（`.stage`） | **5px のまま残る** ❌ | 潰れる |

カスタムプロパティの `var()` は「宣言された要素」で computed-value 時に置換される。
`@theme` が出す `--shadow-neu` は `:root, :host` に宣言されるので、`:root` の時点で
`--neu-lift` が焼き付いた文字列が確定し、子孫はそれを継承するだけになる。
一方 Tailwind のユーティリティは要素側で `--tw-shadow` を宣言するので追随する。

結果、子孫で動かすと「**パネルの影は据え置きで、中のボタンだけ平ら**」という
狙いの真逆の絵になる。`html` 上なら `:root` の `--shadow-neu` 自体が再計算され、
コンポーネントクラスとユーティリティの両系統が同時に沈む。

### 遷移演出に `transform` を使わない

`.stage` に `transform` が乗ると `position: fixed` の包含ブロックが `.stage` へ
切り替わり、以下が壊れる:

- `TweetGenerator` のモバイル常設アクションバー（`fixed inset-x-0 bottom-0`）
- `SongSearchModal` / `PlanListModal`（`fixed inset-0`。`createPortal` を使っていない）

`opacity` は包含ブロックを変えないので安全。`isolation: isolate` も同じ理由で使わない
（常設のスタッキングコンテキストを作ると、上記モーダル `z-50` が Layout の
`sticky z-40` ヘッダーの下に潜る）。

### 無地の間に浮いていてほしい要素は影をリテラルで書く

無地の間は `--shadow-neu*` が**意図的に** 0 へ潰れている。失敗カードのように
「まさにその場面で見えてほしい」ものにトークンを使うと見えなくなる。`.neu-static` を使う。

### View Transitions API を採用しなかった理由

1. `BrowserRouter` 経路では `<Link viewTransition>` が実質 no-op
   （`startViewTransition` に繋がるのは `RouterProvider` の setState 経路だけ）
2. **VT のスナップショットは静止画なので `box-shadow` を補間できない。**
   この演出の要である「影が消えて素材に沈む」が原理的に opacity フェードにしかならない
3. UA スタイルの `::view-transition-group(*)` が 0.25s を持つため、
   `old(root)` だけ上書きしても `finished` の解決時刻がズレる

### 二重チラつきを構造から消す

全ツールが `React.lazy` + `Suspense` なので、素朴に作ると
「無地 → 読み込み中… → 無地」の二重チラつきになる。

`RouteStage` は描画する location を自前で握り、沈み込み完了時に
`startTransition(() => setShown(target))` する。**既に中身を持つ Suspense 境界への
transition 更新では、React 19 は fallback へ切り替えず前の木を保持したまま待つ**ので、
通常のページ遷移で `PageFallback` は原理的に描画されない。

浮上のトリガーは時間ではなく「新しい木が実際に commit された瞬間」なので、
チャンクが遅ければ無地のまま待つだけで、途中で一度浮いてまた沈むことはない。

残るのはハードリロード／直リンクの初回だけ（境界に前の中身が無いので本物の
fallback が出る）。そこは `.stage-fallback` を「文字なしの無地面 ＋ 450ms 遅れて
文言をフェードイン」にして、速い回線では文言自体が視認されずに終わるようにしてある。

### 演出の「間」をロード時間に変える

`prefetchRoute` は `React.lazy` と**同じ import 関数・同じ Promise** を共有する
（`motion/routes.ts` に集約した理由）。`NAVIGATE` の時点で先読みが走るので、
沈み込みの 130ms がそのままチャンクのロード時間になる。

## 演出ではなく「機能」として全レベルで動くもの

「オフ」でも動く。これらは装飾ではないため。

- スクロール復元（react-router v7 は復元しない）
- フォーカスをステージ先頭へ移す
- `aria-live` での遷移先読み上げ
- チャンクの先読み
- チャンク読み込み失敗の検知

### スクロール復元の勘所

- 退避は**旧ページが見えている間**に。無地の最中は既に新しい木が commit されていて
  `scrollY` が新ページの高さでクランプされうるので、そこで保存すると旧ページの記憶を壊す
- 復元は**新しい木がレイアウト済み・かつ画面上は無地**の一瞬に。位置が飛ぶ様子が見えない
- 副作用の順序は `restoreScroll` → `focusStage` → `announce` で固定（`machine.test.ts`）。
  逆にするとフォーカス移動に伴うブラウザのスクロールが復元位置を上書きする
- `bootstrapMotion()` で `history.scrollRestoration = "manual"` にしてある
  （ブラウザ既定の復元と二重にかからないように）

## チャンク読み込み失敗

`netlify.toml` は SPA フォールバック（未知パスを index.html へ 200 で返す）なので、
タブを開いたまま再デプロイされると、古いハッシュのチャンク要求に **JS ではなく HTML が 200 で返り**
`import()` が MIME エラーで reject する（Vite + SPA ホスティングの定番事故）。

演出を被せた状態でこれが起きると「無地のまま永久に待つ」になり、失敗が成功と
見分けられなくなる。三重の網で拾う:

1. 先読みの reject → `FAILED`（通常のページ遷移）
2. `FAILSAFE`（10s）→ `READY` も `FAILED` も来ないまま固まった場合
3. `RouteErrorBoundary` → 初回ディープリンクなど先読みを経由しない経路

## 構成

```
src/motion/
  plan.ts          設定 × OS → MotionPlan（純関数。duration の正本）
  machine.ts       遷移の有限状態機械（純粋リデューサ。effects をデータで返す）
  useRouteStage.ts 唯一の不純な層。effects を setTimeout/startTransition/scrollTo/focus に翻訳
  routes.ts        lazy と先読みが同じ Promise を共有する正本
  settingsStore.ts useSyncExternalStore + localStorage（planStorage.ts と同じ流儀）
  scrollMemory.ts  location.key ごとのスクロール記憶
  useReducedMotion.ts / bootstrap.ts / stageContext.ts
  motion.css       振り付け（ms は書かない。html の --stage-* から受け取る）
```

`machine.ts` は DOM もタイマーも React も router も知らない。だから「遅いチャンク」
「連打」「戻る」「失敗」の経路をブラウザ無しで全部テストできる。

duration の正本は TS 側（`MotionPlan`）で、`html` の `--stage-sink` / `--stage-rise` に
流し込む。CSS には ms を1つも書かない（二重管理をしない）。

## 未確定・オーナー判断待ち

- **既定を「リッチ」にしてよいか。** `--neu-lift` の補間は `html` 配下の全ノードで
  スタイル再計算を起こし、`box-shadow` は GPU 合成できない。低スペック Android で
  `/analyzer` `/ranking` を開くとコマ落ちする可能性がある。`plan.ts` の `resolvePlan` の
  `auto` 分岐 1 行で「控えめ」へ落とせるようにしてある。
  なお**自動降格（フレーム予算を実測してレベルを勝手に変える）は入れていない** —
  明示的に選んだ設定を裏で書き換えると設定 UI の意味が壊れるため。
- **ヘッダーも一緒に沈むが、これでよいか。** `--neu-lift` を `html` で動かす結果、
  ヘッダーのロゴやメニュー項目の影も潰れる。ヘッダー自身のガラス帯と枠線は残るので
  「土台のバーは残ったまま、素材だけが一斉に静まる」絵になる。
- **戻る／進む（POP）にも同じ 380ms を課してよいか。** ブラウザバックは「無料」だと
  期待されている操作なので、`sinkMs` を半分にする非対称もありうる。
- **失敗カードの文言。** 「サイトが更新された可能性があります。再読み込みしてください」。
