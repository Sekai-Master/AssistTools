# 明暗テーマ（ライト / ダーク）

2026-08-01 追加。[porting/design.md](porting/design.md) の「不可侵ライン」は**そのまま維持**していて、
ここで変わるのは**素材の3値と文字の階調だけ**。造形（浮き沈み・角丸・余白）と
ユニットカラーの割り当ては明暗で共通。

---

## 全体像

ニューモーフィズムは結局この3つの関係だけで出来ている。

| トークン | 意味 | ライト | ダーク |
|---|---|---|---|
| `--neu-base` | 素材そのもの | `#f0f0f0` | `#2a2d33` |
| `--neu-lo` | 光の当たらない側の影 | `#bebebe` | `#16181d` |
| `--neu-hi` | 光の当たる側の影 | `#ffffff` | `#3a3f4a` |
| `--neu-ink` | 本文色 | `#333333` | `#e4e6ea` |

`--shadow-neu*` の4本はこの3値を参照するだけになったので、**影の定義はテーマごとに
複製していない**。光源は明暗どちらも左上のまま。

### 暗所で白いハイライトを使わない

`--neu-hi` を `#ffffff` のままにすると、素材ではなく**プラスチックのてかり**に見える。
ベースより少し明るいだけの灰にしてある。影の落差も明所より浅い
（明所 −19 / +6 に対し、暗所は −8 / +8）。暗い面は陰影の階調が出にくいぶん、
落差を付けすぎると「黒く縁取られた板」になる。

## 切り替えの仕組み

**`light-dark()` を使い、値は1箇所にしか書かない。**

```css
:root {
  color-scheme: light dark;              /* 既定＝端末追随 */
  --neu-base: light-dark(#f0f0f0, #2a2d33);
}
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }
```

どちらが採用されるかは `color-scheme` が決めるので、テーマの切り替えでやることは
**`:root` の `color-scheme` を差し替えるだけ**。変数テーブルの再定義は一切要らない。

ダーク用の宣言ブロックを別に持つ設計にしなかったのは、この手のトークンで最も
起きる事故が「片方だけ更新して食い違う」だから。

- 設定は `src/lib/theme.ts`（`motion/settingsStore.ts` と同じ流儀）
- 既定の「自動」では `data-theme` を**付けない**。端末追随はブラウザの仕事に任せる
- 明示的に選んだときのちらつき防止だけ `index.html` のインラインスクリプトで先出しする
  （`main.tsx` は module なので CSS より後に走り、一瞬だけ端末側の配色が見える）。
  ★ キー文字列が index.html と theme.ts に二重にある。変えるなら両方

## Tailwind の色を1箇所で反転させる

`text-slate-500` などはアプリ全体で 300 箇所近く使っている。Tailwind v4 の
ユーティリティは `color: var(--color-slate-500)` を出力するので、**その変数を
`light-dark()` で上書きするだけで全ページの文字が一斉に反転する**。
`dark:` プレフィックスを 300 箇所に撒く必要はない。

階段の向き（番号が大きいほど強い/濃い）は保ったまま、暗所では明るい側へ組み替えている。
状態色（rose / amber / emerald / teal）も同じ方式。暗所では背景色を
「淡い色面」ではなく「色を帯びた暗い面」に置き換える。

### ユニットカラーは明度だけ上げる

`ln (#4455dd)` と `n25 (#884499)` は暗い面に載せると沈んで白文字が読めなくなる。
明度だけ上げ、**色相は動かさない**（ユニットの同一性は色相が担っているため）。

## ロゴアイコン

`icon.png` は「明るい素材の板の上に6色の花弁が乗っている」絵で、**板そのものが
画像に焼き込まれている**。問題が2つある:

1. 板は角丸の四角なのに、**その外側が純白 (`#ffffff`) で埋まっている**。素材は
   `#f0f0f0` なので、明所でも四隅だけ白く見える
2. 暗所ではこの板ごと白い四角として浮く

`scripts/make-header-icons.mjs` が両方を処理した `icon-light.webp` / `icon-dark.webp` を作る。

- **四隅**: 四隅から**塗りつぶし探索**して透過にする。単純な明度の閾値では板の内側の白
  （中央の音符・花弁のハイライト）まで消えるので、四隅から繋がっているものだけを対象にする。
  実測で板は 236〜239・外側は 255 と分離できるので、間の 244 で切っている。
  境界のアンチエイリアスはそのまま alpha の傾きに変換する
- **暗所版**: さらに彩度で重み付けして**中立色（板・影・中央の音符）だけを**暗い素材の
  階調へ移し替える。花弁は彩度が残るので保護され、花弁のふちの柔らかい影は自然に暗側へ落ちる

ヘッダーが解決済みテーマで出し分ける。**favicon は元の `icon.webp` のまま**
（タブの背景色は選べないので、透過させると環境次第で沈む）。

**BINGO のフリーマスに使っている同じアイコンは差し替えない。**
あれは canvas に描いて書き出す画像で、共有先の配色は閲覧者のテーマとは無関係だから。
同じ理由で `planCanvas` 等の書き出し色も固定のまま。

## 画面遷移との関係

[motion-system.md](motion-system.md) の演出は**色に依存していない**。
`--neu-lift`（影の量）・`blur`・`saturate` はどれも素材の色を問わないので、
テーマを足すために遷移側を触る必要はなかった。

例外は「無地の間も浮いていてほしい要素」で影をリテラル書きしている箇所
（`.stage-wait` / `.neu-static`）。ここはトークン参照へ移してある
（`--neu-lift` に潰されないリテラルの *距離* は保ったまま、*色* だけトークン化）。
